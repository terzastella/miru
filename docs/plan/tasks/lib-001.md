## Objective

API libreria completa su Postgres, contratto spec §8, envelope standard:

1. **`server/common/envelope.ts`** — helper unico per tutte le route (definito in `found-003` per auth, qui esteso/riusato): `{ data, meta, error: null | { code, message, details } }`, errori machine-readable non solo HTTP status (§8).
2. Route REST:
   - `GET /api/library` — filtri: `status` (multi), `favorite`, `q` (full-text titolo romaji/english/japanese + note + tag), `tag`, `minScore`, `sort` (tutti gli 8 di `LIBRARY_SORTS`), paginazione. Indici da `found-002`.
   - `POST /api/library` — `{ animeCatalogId }`: upsert `anime_catalog` dalla cache discovery (idempotente), crea `library_entries`, logga `activity_log` ('added').
   - `GET/PATCH/DELETE /api/library/:entryId` — PATCH campi parziali: `status` (transizioni che auto-compilano `startedAt`/`finishedAt` e completano episodi se `done` — stesso comportamento di `store.tsx:260-279`), `userScore`, `notes`, `customTags`, `isFavorite`, date manuali. DELETE = soft delete (`deleted_at`, log 'removed').
   - `POST/DELETE /api/library/:entryId/episodes/:number/watch` — toggle episodio, mantenimento `progress_episodes` via `updateProgress` di `found-002`, transizioni status automatiche (plan→watching, completo→done), doppio log attività.
   - `POST /api/library/:entryId/rewatch` — incremento `rewatch_count`, reset `watched_episodes`, status→watching (spec §7.3).
   - `GET /api/library/sync?since=<ts>` — delta pull §9 (schema `library_entries.updated_at` + `deleted_at`): **solo la base dati, la coda offline e il POST sync sono in Fase 2** (ADR-05).
   - `GET /api/stats/summary` e `GET /api/activity?limit&before` — derivati da `activity_log` (la logica `computeStats` di `store.tsx:465-509` va riprodotta server-side: 1:1, testata).
3. Validazione input Zod su ogni route (spec §17), niente mai fidarsi del client. Solo utenti autenticati (guard better-auth da `found-003`).
4. Il completamento episodi oltre `episodes_total` è rifiutato (400, `error.code` dedicato).
