## Objective

Sostituire l'adapter di persistenza senza toccare la UI — il punto chiave della spec (§3 commento in `store.tsx:26-32`):

1. **`lib/persistence-adapter.ts`**: interface `PersistenceAdapter { read(): PersistedState; apply(mutations): void; }` con due implementazioni:
   - `LocalAdapter` — il codice attuale di `store.tsx:57-82` (localStorage), invariato.
   - `ApiAdapter` — fetch verso le route di `lib-001` (library CRUD, stats, activity, episodes) con: ottimistic update + rollback su errore, debounce/serializzazione delle scritture in coda, gestione rete assente (→ scritture in coda lato client, marcate `pendingSync`), refresh token 401-interceptor.
2. **`MiruProvider`** diventa ibrido: se sessione autenticata (better-auth client da `found-003`) usa `ApiAdapter`; altrimenti `LocalAdapter` (modalità ospite invariata, spec §5). Nessun cambiamento di firma verso le view.
3. Banner guest/account nella UI: swap `app-shell.tsx:67-74` per mostrare stato sessione (chiavi i18n `account.guest*` già esistenti), link a login/register (pagina nuova in `app/auth/login`, stile esistente) e logout.
4. Hydration: primo fetch da API con spinner (stato `ready` già gestito in tutte le view).
5. Struttura di rischio: scritture locali pendenti NON vengono perse su logout improvviso (persistite in IndexedDB se Fase 2 non ancora arrivata → documentare trade-off nel review; la Fase 2 subentra con Dexie e coda duratura).
