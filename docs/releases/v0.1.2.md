## 🇮🇹 Italiano

**MIRU 0.1.2** corregge un difetto dello storico importato e rende visibile un errore di salvataggio.

### Cosa cambia

- **Storico agganciato correttamente**: quando reimportavi un backup su una libreria già popolata, gli eventi restavano legati all'id della voce del backup e non comparivano nella scheda dell'anime. Ora il merge rimappa gli id (`backupEntryId → localEntryId`) e lo storico torna al suo posto.
- **Errore di salvataggio visibile**: se il dispositivo rifiuta la scrittura (spazio esaurito, storage bloccato) compare un avviso, invece di una riga silenziosa in console.
- **Test**: 18 casi, incluso il rimappaggio degli id tra backup e libreria locale.

### Installazione

1. Scarica [**MIRU.exe**](https://github.com/terzastella/miru/releases/download/v0.1.2/MIRU.exe) (14.7 MB)
2. Mettilo dove preferisci e avvialo: i dati restano in `%LOCALAPPDATA%\app.miru.desktop`

Requisiti invariati: Windows 10/11 con WebView2 Runtime, nessuna installazione, nessun Node.js.

### Note

## 🇬🇧 English

**MIRU 0.1.2** fixes a defect in imported history and surfaces a save failure.

### What changed

- **History linked correctly**: re-importing a backup into an already populated library left activity events bound to the backup's entry id, so they never showed up on the anime page. The merge now remaps ids (`backupEntryId → localEntryId`).
- **Visible save errors**: if the device refuses the write (storage full or blocked) you get a notice instead of a silent console line.
- **Tests**: 18 cases, including the entry-id remap between backup and local library.

### Install

1. Download [**MIRU.exe**](https://github.com/terzastella/miru/releases/download/v0.1.2/MIRU.exe) (14.7 MB)
2. Put it anywhere and run it: your data stays in `%LOCALAPPDATA%\app.miru.desktop`

Requirements unchanged: Windows 10/11 with WebView2 Runtime, no installer, no Node.js.

### Integrity

SHA-256, check with `Get-FileHash .\MIRU.exe -Algorithm SHA256`:

```
B7D42960F13A3B534B4FE8CFCF052EAA99259D5160E9F68743F36AA87D6AA18C
```

### Notes

- Upgrade over 0.1.0 and 0.1.1: same data folder, library and catalog are preserved.
- The executable is unsigned: SmartScreen may ask for confirmation ("More info" → "Run anyway").
